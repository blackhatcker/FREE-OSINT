# Security Policy

## Supported Scope

This security policy covers the FreeOSINT.org website, documentation, repository configuration, educational content, scripts, workflows, dependencies, and community contribution process.

## Reporting a Vulnerability

Please do not open public GitHub issues for security vulnerabilities.

Send reports to:

```text
arctic.framework@gmail.com

Include:

affected URL, file, workflow, dependency, or module;
clear reproduction steps;
observed impact;
screenshots or logs when safe;
whether the issue is actively exploitable;
recommended remediation, if known.
Sensitive Findings

Do not include:

secrets;
credentials;
access tokens;
private keys;
personal data;
private records;
exploit code beyond what is strictly necessary to validate the report.
Maintainer Response Targets
Initial acknowledgement: as soon as maintainers are available.
Triage: based on severity.
Fix priority: based on user safety, data exposure risk, abuse potential, and operational impact.
Coordinated Disclosure

We ask reporters to provide reasonable time for remediation before public disclosure.

Maintainers may credit reporters when appropriate and when requested.

Security Controls Recommended for the Repository

The repository should use:

branch protection;
required pull request review;
required status checks;
secret scanning;
dependency review;
code scanning;
signed commits where feasible;
least-privilege repository permissions;
protected release workflow;
periodic review of maintainers and permissions.

# Privacy Notice

FreeOSINT.org is intended to provide open educational content with minimal data collection.

## Privacy Principles

The project should be operated according to these principles:

- collect the minimum information needed;
- avoid unnecessary tracking;
- avoid selling or sharing user data;
- avoid invasive analytics;
- respect user consent where cookies or analytics are used;
- avoid storing sensitive investigative material unless clearly necessary;
- document all third-party services;
- avoid using real personal data in examples;
- anonymize or fictionalize training scenarios.

## User Content

Do not submit the following to public issues, discussions, pull requests, examples, or training modules:

- private personal data;
- credentials;
- protected records;
- classified material;
- illegally obtained information;
- sensitive investigative data;
- private identifiers;
- nonpublic screenshots;
- private social media content;
- private messages;
- leaked data.

## Community Contributions

Contributors must remove personal data from:

- screenshots;
- logs;
- examples;
- datasets;
- reports;
- demonstrations;
- test files.

## Third-Party Services

If the project uses analytics, forms, hosting providers, embedded content, or external services, maintainers should document:

- provider name;
- purpose;
- data collected;
- retention period;
- privacy policy;
- opt-out method where available.

Privacy questions may be sent to:

# Responsible Use Policy

FreeOSINT.org exists to teach lawful, ethical, and privacy-respecting Open Source Intelligence.

OSINT can support journalism, research, fraud prevention, human-rights work, cyber defense, public-interest investigations, compliance, and safety. The same techniques can also be misused. For that reason, this project requires responsible use.

## Allowed Uses

Acceptable uses include:

- education and training;
- authorized security research;
- journalism;
- academic research;
- public-interest research;
- fraud awareness;
- source verification;
- defensive cybersecurity;
- compliance and due diligence;
- personal digital footprint review;
- safety-focused research.

## Prohibited Uses

Do not use this project to support:

- harassment;
- stalking;
- doxxing;
- unlawful surveillance;
- unauthorized access;
- credential theft;
- social engineering against real targets;
- impersonation;
- publication of private personal data;
- targeting private individuals for harm;
- evasion of law enforcement;
- misuse of leaked, stolen, or illegally obtained data;
- bypassing access controls;
- intimidation or coercion.

## Legal Authority

Before conducting any OSINT activity, users must confirm:

- the purpose is lawful;
- the method is lawful;
- the data source is lawful to access;
- platform terms are respected;
- privacy obligations are understood;
- sensitive data is minimized;
- results are handled securely.

## Harm Reduction

Users should:

- collect only what is necessary;
- document assumptions;
- verify sources;
- avoid exposing private people unnecessarily;
- protect notes and reports;
- redact sensitive details;
- avoid public accusations without strong evidence;
- use responsible disclosure channels.

## No Authorization Granted

This project does not grant permission to access any system, account, dataset, platform, private community, private record, restricted database, device, or network.

Users remain solely responsible for their actions.
