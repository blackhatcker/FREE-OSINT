# Code of Conduct

## Our Standard

We are committed to a respectful, inclusive, and safe community for contributors, learners, researchers, journalists, analysts, educators, and maintainers.

Participants are expected to:

- use welcoming and inclusive language;
- respect different experience levels and backgrounds;
- give constructive feedback;
- protect privacy and safety;
- avoid publishing sensitive personal information;
- follow lawful and ethical OSINT practices.

## Unacceptable Behavior

Unacceptable behavior includes:

- harassment;
- intimidation;
- threats;
- doxxing;
- discriminatory language;
- sexualized conduct;
- spam;
- malicious tool submissions;
- unsafe investigative instructions;
- encouragement of privacy invasion;
- unauthorized access guidance;
- stalking or targeted abuse;
- publication of secrets, credentials, private records, or personal data.

## Enforcement

Maintainers may:

- remove content;
- close issues;
- block users;
- reject pull requests;
- restrict participation;
- escalate reports where appropriate.

# Contributing to FreeOSINT.org

Thank you for improving FreeOSINT.org.

Contributions are welcome when they strengthen lawful, ethical, and practical OSINT education.

## Contribution Types

You may contribute:

- new training modules;
- corrections to existing lessons;
- vetted OSINT resources;
- safer wording for risky content;
- accessibility improvements;
- documentation updates;
- translations;
- technical fixes;
- security hardening improvements;
- content review improvements.

## Contribution Rules

All contributions must:

1. support legitimate education, research, journalism, security, or public-interest work;
2. avoid instructions for harassment, stalking, doxxing, unauthorized access, evasion, credential theft, or abuse;
3. include sources where factual claims are made;
4. explain legal and ethical boundaries;
5. respect privacy and data minimization;
6. avoid publishing personal data, secrets, tokens, credentials, or private identifiers;
7. follow the module template in `docs/content-authoring/module-template.md`;
8. include safety warnings where misuse is possible;
9. avoid unsupported claims;
10. avoid copying third-party copyrighted content without permission.

## Pull Request Process

1. Fork the repository.
2. Create a branch named `docs/<topic>`, `module/<topic>`, `fix/<topic>`, or `security/<topic>`.
3. Add or update documentation.
4. Run a self-review using `templates/content-review-checklist.md`.
5. Submit a pull request using `.github/PULL_REQUEST_TEMPLATE.md`.

## Maintainer Review

Maintainers may request edits where content is:

- unclear;
- unsafe;
- unsupported;
- outdated;
- legally risky;
- privacy-invasive;
- inconsistent with FreeOSINT.org’s mission;
- inconsistent with the responsible-use policy.

## Prohibited Contributions

Do not contribute material that teaches or enables:

- credential theft;
- unauthorized access;
- bypassing authentication;
- stalking;
- doxxing;
- harassment;
- unlawful surveillance;
- malicious automation;
- evasion of law enforcement;
- misuse of leaked or stolen data;
- exploitation of private individuals.
